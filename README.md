# PKAOCR

在本地进行发票OCR，实物图以及购买凭证的收集，并整理成规范文件夹

## 环境搭建

已适配并验收环境：macOS 27，Windows11

将项目下载到本地
```bash
git clone https://github.com/5H2ydrogen/PKAOCR.git
```
### macOS/Linux
```bash
uv sync --locked
uv run --locked pyocrpka --prepare-models
uv run --offline --locked pyocrpka
```

如果本机 uv 的默认缓存无写入权限（当前受限开发环境中出现过），使用项目缓存：

```bash
UV_CACHE_DIR=.uv-cache uv sync --locked
UV_CACHE_DIR=.uv-cache uv run --offline --locked pyocrpka --prepare-models
UV_CACHE_DIR=.uv-cache uv run --offline --locked pyocrpka
```
启动命令 
```bash
uv run --offline --locked pyocrpka
```
也可以直接在venv中直接运行main.py
### Windows

先安装[Python](https://www.python.org/)

打开Windows 10/11 的 PowerShell

1. **安装 uv。** 打开 PowerShell，执行：

   ```powershell
   winget install --id=astral-sh.uv -e
   ```

2. **进入项目

   ```powershell
   uv python install 3.12
   uv sync --locked --python 3.12
   uv run --offline --locked pyocrpka --prepare-models
   ```

3. **启动程序。** 后续在项目目录执行：

   ```powershell
   uv run --offline --locked pyocrpka
   ```
也可直接使用 Windows 虚拟环境解释器启动

# 下面是AI

## 使用流程

1. 填写工单号和姓名；选择“微信”或“支付宝”，以及指定的 11 个类别之一。两组均默认不选。
2. 选择 1 个发票（PDF / PNG / JPG / JPEG）和至少 1 张付款图片（PNG / JPG / JPEG）。查验 PNG 和实物图片为选填；选择后仍验证真实格式，改后缀不能绕过验证。
3. 四组文件区均只有“添加、删除”按钮。发票和查验各限一个，更换前先删除；付款凭证和实物可多次添加，拖动列表调整顺序，按最终顺序编号。双击图片预览；双击 PDF 用系统默认应用打开。
4. 点击“开始识别”。PDF 优先读取文字层，字段不足时渲染页面并使用本地 RapidOCR；图片发票使用本地 OCR。识别和生成均在工作线程执行。
5. 对照原票核对日期、发票号、价税合计及每一行商品。所有结果都能修改，可添加/删除商品行。发票号码使用普通文本输入框；多个候选号码会显示在警告区，需要核对原票后手动填写最终值。当前一次只处理一张发票，更换发票会清空旧识别结果。

   明细列名及顺序与发票一致：项目名称、规格型号、单位、数量、单价、金额、税率/征收率、税额。不提供单独的含税金额输入列，输出含税总价自动计算。

6. 缺失字段保持空白。金额冲突和不完整明细显示警告；不会为了凑总额修改原始识别数值。核对后勾选确认框。任何输入更改都会撤销旧确认。
7. 点击“生成报销文件”。六组必填缺失时同时显示红字并阻止生成，查验和实物不填也可生成。已选文件消失、损坏、类型错误仍会阻止生成。成功后显示完整目录，点击“打开输出文件夹”。

发票查验图片只是一份材料，程序不联网执行发票真伪查验。

## 模板与字段映射

模板位于 `other/工单号_发票号/`，必须保留原文件名。两份均为 `Sheet1`，第一行为表头，发布版第二行起为空白并保留原有样式；原示例数据、批注及个人元数据已清理。程序加载模板并填写数据，保留列宽、字体、边框、填充、对齐、工作表名和表头，多商品复制样式。正常使用时模板绝不保存或改写。

表1有效数据列 A:I，J2 原示例说明已清空。原文件延伸到第18行的空白样式区保留；没有合并单元格、Excel Table 或额外公式。

| 列 | 原表头 | 写入值 |
|---|---|---|
| A | 工单号 | 用户输入 |
| B | 姓名 | 用户输入 |
| C | 发票金额 | 价税合计 |
| D | 支付方式 | 微信 / 支付宝原文 |
| E | 发票号码 | 确认后的字符串 |
| F | 效验码后六位 | 有则填写，否则空 |
| G | 发票代码 | 有则填写，否则空 |
| H | 开票日期 | Excel 日期 |
| I | 备注 | 空 |

表2有效列 A:Q，R2 原示例说明已清空；没有合并单元格或 Excel Table。

| 列 | 原表头 | 写入值 |
|---|---|---|

| B | 开票日期 | Excel 日期 |

| E | 支出内容 | 本行商品名称 |

类别严格为：重装、三步、四步、哨兵、无人机、飞镖、管理、宣传、硬件、新生培训、场地。每行使用相同的最终类别、付款方式。

**K2 原公式问题已修复：** 原示例 `=H2+I2+J2` 忽略数量。输出不保留该公式，使用 Decimal 验证后的数值：优先“本行金额 + 本行税额”，金额缺失但数量和单价明确时使用“数量 × 单价（四舍五入至分）+ 本行税额”。任一必要值未知时 K 留空并警告。运费无数据时始终是真空白，不将其当作 0。整张票的总额只填表1 C2，不重复分配给每条商品。合计相差1分钱也会显示警告；数量乘单价按分四舍五入后再核对。

输出副本中的付款方式、类别下拉选项与 GUI 保持一致；不修改原始模板。

发票号、工单号、姓名和商品名按文本写入，防止科学计数法和公式注入。金额为 Excel 数值，日期为日期值。空白不是“无”或“未知”。规格型号、税率保留在结构化数据及编辑界面中，现有模板无对应列，因此不会挤占其他字段。

模板工作表/表头/合并区域改变，或第3行以后新增非空数据时，程序停止生成并提示恢复原模板。

## 输出位置与安全

输出根目录始终为项目根目录下的 `out/`，不依赖 PyCharm 启动目录。下列 `工单号_发票号` 均来自最终确认信息：

```text
out/
└── 工单号_发票号/
    ├── 工单号_发票号_报销材料/
    │   ├── 工单号_发票号_实物/
    │   │   ├── 工单号_发票号_实物1.jpg
    │   │   └── 工单号_发票号_实物2.png
    │   ├── 工单号_发票号_付款凭证/
    │   │   ├── 工单号_发票号_付款凭证1.jpeg
    │   │   └── 工单号_发票号_付款凭证2.png
    │   ├── 工单号_发票号_发票.pdf
    │   └── 工单号_发票号_发票查验.png
    ├── 工单号_发票号_表1.xlsx
    └── 工单号_发票号_表2.xlsx
```

照片数量不限于两张。实物和付款凭证按原格式、原扩展名、原始字节复制：PNG输出PNG，JPG输出JPG，JPEG输出JPEG，扩展名大小写也保留。只按列表顺序重命名文件主体，不压缩、不转码、不更改透明度，不移动、删除或修改原材料。复制前后校验 SHA-256 和真实格式，Excel 保存后重新打开核验字段与文件数量。上面的文件树仅举例，实际后缀以每张上传图片为准。

未选查验时不生成查验图片，未选实物时保留空的实物目录。PNG / JPG / JPEG 发票在本地真正转换为 PDF 输出，继续使用原有 `工单号_发票号_发票.pdf` 命名；原始图片不修改。PDF 输入仍原字节复制。

工单号拒绝路径分隔符、控制字符、非法文件名字符及过长输入，发票号仅允许有效数字格式。拒绝符号链接 `out`。在 `out/.reimbursement-*` 临时目录完成全部结果，检查后用 macOS 原子排他重命名发布。已有同名目录（即使为空）也不覆盖、不自动改名。错误时清理本次临时结果；强制断电/杀进程可能留下隐藏的临时目录，可在确认没有任务运行后手动清理，正式目录不会提前出现。

## 项目结构

```text
src/main.py                 PyCharm 直接启动入口
src/pyocrpka/app.py          CLI、GUI 启动、脱敏日志
src/pyocrpka/gui.py          中文界面、文件列表、后台工作线程
src/pyocrpka/models.py       发票/明细/报销数据、Decimal 校验
src/pyocrpka/validation.py   必填校验、真实文件格式验证
src/pyocrpka/recognition.py  PDF 提取、逐页 OCR 回退、多票检查
src/pyocrpka/ocr.py          本地模型准备、SHA-256、CPU 推理
src/pyocrpka/parser.py       标签/动态表头布局解析
src/pyocrpka/excel.py        模板检查、填充、回读验证
src/pyocrpka/output.py       材料复制、临时目录、排他发布
src/pyocrpka/paths.py        以项目根目录为基准的路径
src/pyocrpka/assets/         软件图标及界面图片
models/                     三个 ONNX 模型和校验清单
other/工单号_发票号/         空白模板；本地私人参考材料不提交Git
tests/                      pytest，全部使用独立临时目录
scripts/acceptance.py       真实样例验收，输出在独立系统临时目录
artifacts/                  验收报告与界面截图（不参与运行）
logs/app.log                轮转错误日志，无完整发票/姓名/凭证内容
```

主要依赖为 Python 3.12、PySide6、openpyxl、PyMuPDF、Pillow、RapidOCR-ONNXRuntime 和 ONNX Runtime CPU；pytest 为开发依赖。Pillow用于验证图片实际格式和可读性，付款/实物输出模块不再使用图片转换依赖。RapidOCR 1.4.4 自带 PP-OCRv4 检测/识别及移动方向分类模型，不引入 PaddlePaddle、Torch 或 CUDA。

## 常见问题和边界

- **红字必填提示：** 补齐对应字段，付款方式/类别必须主动选择。人工补发票号后仍需勾选核对确认。
- **模型尚未准备/校验失败：** 运行 `--prepare-models`；损坏模型先移走再重新准备。程序不自动联网修复。
- **数字或日期错误：** 数值输入十进制数字；日期使用 `YYYY-MM-DD`，不接受不存在的日期。
- **金额不一致：** 核对数量、未税单价、未税整行金额和税额。保留冲突必须明确勾选确认。程序不分摊总金额、不猜测运费。
- **扫描件不清晰、罕见布局或旋转：** 尽量使用原始电子 PDF；无法确认的字段留空并人工补充。没有经过大规模票种准确率评估，不保证所有布局自动识别。
- **发票号码：** 支持常见普通增值税发票 8 位、数电发票 20 位；代码可为 10/12 位。其他特殊票据格式不在本版本内。
- **多页/多张：** 同一张发票的续页可合并商品行。多页若出现不同发票号，或有页面无法确认归属，会要求拆分。单页拼接多个发票标题/号码也会拒绝。模糊扫描件无法可靠判断多票时应由用户先拆分，不能靠人工改号绕过。
- **文件格式不符：** 用图片工具实际导出为 JPEG 或 PNG，不能只改后缀。程序重新检查文件能否解码。
- **目标已存在：** 检查已有报销材料后自行决定如何处理，程序不会覆盖或添加编号。
- **模板错误：** 将两份原始 `.xlsx` 放回指定位置，不要把已填写的报销表当模板。
- **任务进行中：** 界面禁止更改输入和重复生成，暂缓关闭窗口，完成或失败后恢复。
- **权限/磁盘错误：** 检查项目 `out` 可写及磁盘空间；日志仅记录异常类型和代码位置。

本版本优先适配当前 macOS；Linux 提供 `renameat2` 时可安全发布但未在本机验收，Windows 暂不支持排他目录发布。当前132项自动测试通过（含透明图标、1×/2×/3×头像、原格式材料输出、两张问题图片的OCR回归、GUI编辑及Excel输出）。最新发布检查见 [上线前检查](docs/上线前检查.md)；本地历史记录见 `artifacts/项目检查.md` 和 `artifacts/验收报告.md`。
